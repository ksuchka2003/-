# Обновление уже опубликованного книжного клуба

Обновление меняет главную и каталог, упрощает пустые экраны, добавляет синхронизацию профиля и всей личной библиотеки. Личные данные хранятся в Supabase с доступом только владельцу через RLS; публикация другим членам клуба остаётся отдельным согласием.

## 1. Сохраните прежние данные

На каждом устройстве со своими книгами: **Профиль → Экспорт JSON**. Сохраните файлы до обновления. Старые книги из IndexedDB не удаляются.

## 2. Выполните новую SQL-миграцию

В вашем проекте Supabase откройте **SQL Editor → New query**. Вставьте целиком содержимое:

`supabase/migrations/202610250002_private_library.sql`

Нажмите **Run** один раз. Миграцию **001 повторно не запускайте**: существующие книги клуба, участники и встречи должны сохраниться.

Если используется Supabase CLI с отслеживаемыми миграциями, примените `npx supabase db push` из каталога приложения. Если 001 ранее запускалась вручную, сначала согласуйте историю миграций либо выполните 002 через SQL Editor.

## 3. Обновите серверные функции

Разверните обновлённые **telegram-auth** и **club-api**, включая актуальные общие модули `_shared`. Из каталога `book-club`:

```sh
npx supabase login
npx supabase link --project-ref YOUR_PROJECT_REF
npx supabase functions deploy telegram-auth
npx supabase functions deploy club-api
```

`YOUR_PROJECT_REF` — идентификатор вашего существующего проекта. Функция уведомлений и её расписание для этого обновления не меняются.

## 4. Назначьте свой аккаунт администратором

В Supabase: **Edge Functions → Secrets**. Добавьте или исправьте секрет:

- Name: `INITIAL_ADMIN_TELEGRAM_ID`
- Value: **ваш числовой Telegram ID**.

Это не username, не номер телефона и не токен BotFather. ID виден в новом **Профиле** после успешного входа. Если вход ещё не работает, получите свой `message.from.id` из личного /start через Telegram Bot API getUpdates на своей машине, как описано в DEPLOYMENT.md.

`TELEGRAM_BOT_TOKEN` остаётся серверным секретом. В `ALLOWED_ORIGINS` для вашего сайта должно быть `https://ksuchka2003.github.io` — без пути `/-/`.

Обновлённая функция повышает до admin и уже существующего участника с этим ID. После закрытия и повторного открытия Mini App: **Профиль → Управление клубом**. Вручную назначать роль через frontend не нужно.

## 5. Обновите приложение на GitHub

В вашем репозитории `ksuchka2003/-` приложение находится в папке **book-club**. Замените там файлы обновлённым исходным кодом, включая новые файлы из `src` и SQL. Не загружайте `node_modules`, `dist`, `.env` и отчёты тестов.

Сохраните рабочий workflow **в корне репозитория**: `.github/workflows/pages.yml`. Он должен собирать из `book-club` и публиковать `book-club/dist`. Архив **book-club-update.zip** уже подготовлен с такой структурой: в нём рядом находятся `book-club/` и корневая `.github/`. Отдельно приложен готовый `pages.yml`.

После сохранения нового коммита: **Actions → Публикация GitHub Pages (вручную) → Run workflow → main → Run workflow**. Запустите новый workflow на новом коммите. Кнопка Re-run старого запуска соберёт старый код.

## 6. Проверьте оба устройства

1. Полностью закройте Mini App и откройте заново из бота на обоих устройствах. Если осталась старая версия, перезагрузите страницу Mini App; не очищайте её данные до экспорта.
2. В **Профиле** должны совпадать Telegram ID, имя и роль. После загрузки должна появиться отметка **Синхронизировано**.
3. Создайте книгу на первом устройстве. Вернитесь в приложение на втором либо нажмите **Профиль → Синхронизировать**. Проверьте заметки, страницы и цитаты.
4. Если раньше книги сохранялись в локальном режиме, в профиле появится **Книги с этого устройства → Перенести в мой аккаунт**. Перенос выполняется только по вашему нажатию. Исходная локальная библиотека сохраняется.
5. Если старые данные находятся в разных браузерах, можно объединить их JSON-файлы через импорт. Одинаковые UUID и общие книги не дублируются при импорте. Полная замена заменяет библиотеку на всех устройствах после синхронизации; для неё в аккаунте нужен интернет, чтобы учесть всю облачную библиотеку.

При изменении одного поля с двух устройств обе версии сохраняются в профиле до выбора. При отсутствии связи данные остаются на устройстве; подтверждение синхронизации появляется только после ответа сервера.
