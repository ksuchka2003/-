## Что проверяют тесты

- IndexedDB: издание, индивидуальный объём, расчёт процента, диапазоны страниц, цитаты, корзина и 30 дней, JSON и атомарность при некорректном файле.
- Приватность: личные данные синхронизируются только в owner-only хранилище; приватная запись не попадает в публичную очередь; заметки и приватный отзыв не входят в payload публикации прогресса.
- Очередь: сохранение при ошибке сети, повтор без дубликатов, более новая редакция при старом подтверждении, разделение аккаунтов, приоритет отключения приватности.
- Сохранение чужой цитаты: собственный UUID, источник, приватность по умолчанию, повторное сохранение отклоняется.
- Поиск: работа второго API при отказе первого, кеш и ручной ввод при полном отказе.
- Telegram HMAC: корректная подпись, подмена ID, истёкший/будущий auth_date, повторяющиеся параметры.
- PostgreSQL: миграции выполняются последовательно, вторая применяется поверх существующего клуба; закрытый доступ, role escalation запрещён, Telegram ID не раскрываются другим членам, RLS и приватность колонок, запрет записи через виды даже при широких default privileges, лайки и cascade, версии/запоздалые операции, диапазон прогресса, идемпотентное одобрение заявки и дубликаты, несколько главных книг, встречи и уведомления, отзыв доступа при активном JWT.
- Личная синхронизация: две независимые Dexie-базы используют настоящую SQL RPC в PGlite. Проверены книги, страницы, отзывы, заметки, цитаты, избранное, корзина, независимые поля, конфликт одного поля с сохранением обеих версий и выбором, удаление/tombstones, правка во время отправки, повтор после сети и после ошибки согласования публикаций, owner-only доступ (включая запрет администратору клуба), атомарный отказ некорректного пакета, отзыв доступа. Отдельно проверены профиль, частичные разрешения приватности и назначение уже существующего участника администратором только через service_role.
- RTL: закрытый контент без сессии, пустые состояния без служебного текста и выдуманных биографий, главная с текущей книгой/ближайшей встречей, ссылки, поиск трёх разделов каталога, порядок нескольких главных книг и явная админская кнопка.
- Playwright: CRUD книги и сохранение после перезагрузки; цитата/избранное/корзина/восстановление; запись прогресса офлайн после загрузки; экспорт/импорт с подтверждением полной замены; обе темы и отсутствие горизонтальной прокрутки на мобильной ширине. Дополнительно проверено отсутствие ложного сообщения об отказе IndexedDB при повторном запуске React StrictMode.
- Дополнительные Playwright-сценарии: один аккаунт в двух изолированных browser contexts — библиотека, приватные заметки, цитаты, профиль, офлайн-прогресс, удаление и отсутствие случайной публичной отправки; ошибка авторизации без автоматического перехода в локальный режим. Для них HTTP API и Telegram initData заменяются тестовыми обработчиками исключительно в тестовом сервере. Production-код не содержит обхода авторизации.

## Границы проверки

PGlite выполняет PostgreSQL, но использует тестовую `auth.uid()` и роли. Реальные Hosted Supabase Auth/GoTrue, PostgREST, Edge Runtime, Cron/Vault, BotFather и доставку Telegram нельзя подтвердить локальными тестами без настроенных пользовательских ресурсов. Две браузерные сессии с тестовым API подтверждают клиентский сценарий; реальную авторизацию и перенос данных дополнительно проверяйте внутри Telegram после развёртывания.

Прямой `deno check` HMAC-модуля выполнен успешно. Ранее проверка полного графа Deno в Windows sandbox останавливалась на `Failed canonicalizing` npm-кеша scoped-пакета Supabase; отдельно выполнен `tsc` Edge-кода с типами Supabase. Полный `deno check` включён в Ubuntu CI. Для предыдущего обновления уже успешно выполнены GitHub Pages workflow, облачное развёртывание telegram-auth/club-api, проверка CORS, отказа при поддельных initData и запрета анонимного чтения личной библиотеки. Эти проверки не заменяют вход с настоящими initData и проверку доставки сообщений.

Playwright использовал установленный Chromium 148.0.7778.97, скопированный в рабочий каталог из локального браузерного кеша из-за ACL исходного каталога. Для обычного запуска/CI предусмотрена стандартная установка `npx playwright install chromium`; специальных путей в исходном коде нет. Только при локальной необходимости можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` и `E2E_PORT`.

Перед реальным использованием выполните интеграционную проверку двумя Telegram-аккаунтами по DEPLOYMENT.md. Успешная локальная сборка не означает, что секреты, RLS проекта и расписание уже настроены в вашем аккаунте.

Новые проверки: миграция 003 поверх существующей базы; закрытые черновики, общее голосование, один изменяемый голос, закрытие при модерации и запрет обхода RPC; приглашения с хешами, отзыв/срок/лимит использований, повторное погашение, предел 20 участников и запрет возвращения отключённого участника по общей ссылке. Проверены защищённый webhook, отказ перезаписывать чужой webhook, команды в личном чате и группе, скрытие кнопки «Назад» Telegram при запуске. В Playwright добавлен поиск ISBN с кириллической Х по Enter без отправки формы и навигация на ширине 320 px. Визуально проверены форма, список участников и голосование, отсутствие горизонтального переполнения на 320/600/900/1440 px.

Мобильная совместимость: вход и первоначальная синхронизация проверяются с отключёнными `AbortSignal.timeout` и `AbortSignal.any`. Транспорт использует обычный AbortController и очищает таймеры/обработчики; тестируются таймаут, отмена и работа без новых статических методов. Таймаут ответа отличается в интерфейсе от сетевого отказа. Это проверка совместимости, а не гарантия доступности Supabase у каждого мобильного оператора.

Календарь 004: полная и частичная занятость, общее время, неизвестный ответ, МСК на разных устройствах, удалённые участники, повторные RSVP без дубликатов, комментарии, конфликт времени, пересечение встреч, перенос и отмена. Playwright проверяет копию календаря на втором устройстве, приглашение с комментарием и отказ сохранения без ложного успеха.
