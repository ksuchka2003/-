# Проверка сценария чтения — 9 ноября 2026

Перед публикацией выполнены TypeScript, Vitest, сборка Vite, проверка TypeScript Edge Functions и мобильные сценарии Playwright. Команды: npm run check, npm run check:edge, npm run test:e2e.

- 188 тестов Vitest: в том числе все миграции 001–016 в изолированном PostgreSQL PGlite, RLS, защита владельца, публикации, отзывы после завершения/отказа от книги, реакции, комментарии, отчёты и история периодов.
- 40 сценариев Playwright: локальная библиотека, два устройства, отсутствие сети, отдельные заметки/мысли/отзывы, обложки, полки, карточки, оформление, участие в чтении, реакции к комментариям, дубликаты, отчёт и существующие функции клуба.
- SQL: отказ от текущей книги запрещает новые собственные публикации до смены решения; поздние публикации после завершения доступны. Приватные записи недоступны другим участникам и администратору клуба. Записи клуба доступны действующим участникам.
- Реакции: один плюс или минус на участника и объект, переключение/отмена; комментарии принадлежат автору; удаление публикации очищает обсуждение. Независимая сохранённая цитата не требует оригинала.
- История прогресса: идемпотентные повторы, исходная отметка при импорте, исправления и смена издания без ложного прироста, статистика по периодам/участникам, порядок завершения, исключение прочитавших до клуба, сохранение предыдущего периода при новом чтении.
- IndexedDB: отдельные записи, перенос прежней заметки с защитой от параллельной правки, импорт старого и нового JSON, полки, перенос настроек и записей на второе устройство. Одновременное добавление клубной книги не создаёт локальный дубликат; редактор не стирает параллельный прогресс, заметки и полки.
- Интерфейс: ширина 320 px, светлая/тёмная темы, прокрутка всей панели выбора книги, отдельный поиск обложки после открытия, свёрнутый источник цитат, пустые состояния, подтверждения удаления. Ручное добавление не вызывает интернет-поиск.

HTTP-фикстуры в Playwright изолируют сценарии от реального клуба и не являются подтверждением входа на физическом телефоне. Проверки HMAC/JWT/RLS выполняются отдельно; в коде приложения нет тестового обхода авторизации. Проверка опубликованных файлов дополнительно использует изолированные HTTP-ответы и блокирует реальные облачные записи. Реальные участники и личные библиотеки не заполняются тестовыми данными; тестовые уведомления не отправляются.

Ограничения: отчёт отражает отметки прогресса, а не длительность чтения. История до внедрения функции не выдумывается. Без сети несколько правок одной записи могут объединиться в последнюю; сервер сохраняет подтверждённые изменения. Доставка личных напоминаний зависит от доступности Supabase и Telegram.
