**Управление и единый стиль, 8 ноября:** короткое меню администратора, упрощённые формы и спокойные списки. При установленных 001–012 обновите только frontend; SQL, функции и Cron не меняются. Подробности: [CALM_ADMIN.md](CALM_ADMIN.md).

**Упрощение библиотеки 8 ноября: единый поиск, карточка своей книги и компактные фильтры.** При установленных 001–012 обновите только frontend. Новая SQL-миграция и развёртывание Edge Functions не требуются. Подробности: [FRIENDLY_LIBRARY.md](FRIENDLY_LIBRARY.md).

**Обновление 8 ноября: 012 — корзина книг, быстрый прогресс и черновики.** Если 001–011 уже установлены, примените только `202611080012_personal_book_trash.sql`, затем опубликуйте frontend. Серверные функции и Cron для этого обновления не меняются. Подробности: [QUICK_LIBRARY.md](QUICK_LIBRARY.md). Инструкции ниже относятся к установке предыдущих обновлений при необходимости.

Текущее обновление после 001–008: **009, 010, 011**, по порядку из `supabase/migrations`. 009 возвращает уведомления в личный чат с ботом и отключает группы. 010 добавляет атомарный выбор текущих книг галочками. 011 добавляет серверные шуточные награды. Удалены фотоцитаты, ISBN и поле ссылки на обложку из форм; упрощены личные статусы и оформление. См. [SIMPLE_CLUB.md](SIMPLE_CLUB.md) и [MEETINGS.md](MEETINGS.md).

Если ещё нет 007, сначала примените `202611060007_reader_covers.sql`: личные обложки в общем прогрессе. См. [READER_UI.md](READER_UI.md).

Для установки без 006 сначала выполните `202611060006_club_memory.sql`: вопросы и итоги встреч, главы и статистика. См. [CLUB_MEMORY.md](CLUB_MEMORY.md).

Если ещё не применялась 005: сначала выполните `202611060005_simple_club.sql`, обновите `notifications` и настройте расписание по [MEETINGS.md](MEETINGS.md). Она отключает календарь, добавляет фотоцитаты и общий прогресс клубных книг.

Для обновления с голосованиями, приглашениями без ID, командами в группе после миграции 002 выполните также **003**: `supabase/migrations/202610310003_polls_and_invites.sql`. Разверните `telegram-bot` вместе с `telegram-auth` и `club-api`. Подробности, секреты webhook и ограничения поиска описаны в [COMMUNITY.md](COMMUNITY.md).

Обновление меняет главную и каталог, упрощает пустые экраны, добавляет синхронизацию профиля и всей личной библиотеки. Личные данные хранятся в Supabase с доступом только владельцу через RLS; цитаты и отзывы публикуются по отдельному согласию; прогресс книг из каталога клуба виден участникам.

## 1. Сохраните прежние данные

На каждом устройстве со своими книгами: **Профиль → Экспорт JSON**. Сохраните файлы до обновления. Старые книги из IndexedDB не удаляются.

## 2. Выполните новую SQL-миграцию

Для установки, где уже применены 001–008: в Supabase откройте **SQL Editor → New query**. Вставьте целиком содержимое:

`supabase/migrations/202611060009_private_notifications.sql`, затем `202611060010_simple_book_selection.sql`, затем `202611060011_reading_awards.sql`.

Нажмите **Run** один раз. Уже применённые миграции повторно не запускайте: существующие книги клуба, участники и встречи должны сохраниться. При обновлении более старой установки сначала примените недостающие 002–008 по порядку из `supabase/migrations`.

Если используется Supabase CLI с отслеживаемыми миграциями, примените `npx supabase db push` из каталога приложения. Если миграции ранее запускались вручную, сначала согласуйте историю миграций либо выполните только недостающие через SQL Editor.

## 3. Обновите серверные функции

Разверните обновлённые **telegram-bot** и **notifications**, включая актуальные общие модули `_shared`. Из каталога `book-club`:

```sh
npx supabase login
npx supabase link --project-ref YOUR_PROJECT_REF
npx supabase functions deploy telegram-bot
npx supabase functions deploy notifications
```

`YOUR_PROJECT_REF` — идентификатор вашего существующего проекта. Расписание остаётся прежним. Обновите защищённую конфигурацию webhook и обновите личное меню бота по [MEETINGS.md](MEETINGS.md).

## 4. Назначьте свой аккаунт администратором

В Supabase: **Edge Functions → Secrets**. Добавьте или исправьте секрет:

- Name: `INITIAL_ADMIN_TELEGRAM_ID`
- Value: **ваш числовой Telegram ID**.

Это не username, не номер телефона и не токен BotFather. ID виден в новом **Профиле** после успешного входа. Если вход ещё не работает, получите свой `message.from.id` из личного /start через Telegram Bot API getUpdates на своей машине, как описано в DEPLOYMENT.md.

`TELEGRAM_BOT_TOKEN` остаётся серверным секретом. В `ALLOWED_ORIGINS` для вашего сайта должно быть `https://ksuchka2003.github.io` — без пути `/-/`.

Обновлённая функция повышает до admin и уже существующего участника с этим ID. После закрытия и повторного открытия Mini App: **Профиль → Управление клубом**. Вручную назначать роль через frontend не нужно.

## 5. Обновите приложение на GitHub

В вашем репозитории `ksuchka2003/-` приложение находится в папке **book-club**. Замените там файлы обновлённым исходным кодом, включая новые файлы из `src` и SQL. Не загружайте `node_modules`, `dist`, `.env` и отчёты тестов.

Сохраните рабочий workflow **в корне репозитория**: `.github/workflows/pages.yml`. Он должен собирать из `book-club` и публиковать `book-club/dist`. Архив **book-club-update.zip** уже подготовлен с такой структурой: в нём рядом находятся `book-club/` и корневая `.github/`. Отдельно приложен готовый `pages.yml`.

После сохранения нового коммита: **Actions → Публикация GitHub Pages (вручную) → Run workflow → main → Run workflow**. Запустите новый workflow на новом коммите. Кнопка Re-run старого запуска соберёт старый код.

## 6. Проверьте оба устройства

1. Полностью закройте Mini App и откройте заново из бота на обоих устройствах. Если осталась старая версия, перезагрузите страницу Mini App; не очищайте её данные до экспорта.
2. В **Профиле** должны совпадать Telegram ID, имя и роль. После загрузки должна появиться отметка **Синхронизировано**.
3. Создайте книгу на первом устройстве. Вернитесь в приложение на втором либо нажмите **Профиль → Синхронизировать**. Проверьте заметки, страницы и цитаты.
4. Если раньше книги сохранялись в локальном режиме, в профиле появится **Книги с этого устройства → Перенести в мой аккаунт**. Перенос выполняется только по вашему нажатию. Исходная локальная библиотека сохраняется.
5. Если старые данные находятся в разных браузерах, можно объединить их JSON-файлы через импорт. Одинаковые UUID и общие книги не дублируются при импорте. Полная замена заменяет библиотеку на всех устройствах после синхронизации; для неё в аккаунте нужен интернет, чтобы учесть всю облачную библиотеку.

При изменении одного поля с двух устройств обе версии сохраняются в профиле до выбора. При отсутствии связи данные остаются на устройстве; подтверждение синхронизации появляется только после ответа сервера.
